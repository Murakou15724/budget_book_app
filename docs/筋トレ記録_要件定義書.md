# 筋トレ記録機能 要件定義書

## 0. 位置づけ

本書は `/home/murakamiko/projects/001_personal_2026/998_個人用/筋トレ管理_2026.xlsx`（Excel「筋トレ Daily Quest Dashboard」）の内容・運用ルールを分析し、それを本アプリ（家計簿アプリ）内の独立機能としてRailsに再構築するための要件定義書である。既存Excelのシート構成・マスタデータ・XP/レベル計算ロジックを踏襲しつつ、数式の壊れやすさや1日1種目しか記録できない制約を解消することを目指す。

- 分析対象: `筋トレ管理_2026.xlsx`（シート: Dashboard / Workout_Log / Weekly_Review / Menu_Master / Badges / 使い方）
- 移行先: 本リポジトリ内の新規リソース群（家計簿機能とは独立、ホーム画面から`/workouts`配下に遷移）

最終更新: 2026-09-08（実装開始時点）

## 1. 背景・目的

利用者はこれまでExcelで筋トレ記録「Daily Quest Dashboard」を運用していた。日々の実施内容を記録し、XP・レベル・称号・連続日数を自動計算してゲーム風に可視化することで、習慣化のモチベーションを保っている。

Excel運用には以下の課題がある。

- 1日1種目しか記録できない（複数部位を鍛えた日でも1行にまとめるしかない）
- 366行を日付分あらかじめ用意する構造で、数式の複製漏れ・崩れのリスクがある
- 「現在Lv」の算出式（`INT(総XP/250)+1`）と称号（Badges）のしきい値が独立しており、数字上の整合が取れていない

本アプリでは、Excel版の「記録のしやすさ」「ダッシュボードでの可視化」「XP・レベル・称号によるゲーミフィケーション」という体験は維持しつつ、1日に複数種目を記録できるようにし、レベルと称号のロジックを称号テーブルに一本化する。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 実施 | その日、筋トレを行ったこと(Workout_Logの「実施」に相当) |
| 軽め | 実施はしたが軽度の運動に留めた日。種目の詳細を問わず固定XPを付与 |
| 休み | 意図的な休養日。サボりと区別して記録する |
| ワークアウトエントリー | 1日の中の1種目分の記録（セット・回数・重量・時間・RPE） |
| RPE | Rate of Perceived Exertion。主観的なきつさを1〜10で入力する指標 |
| XP | 実施内容から自動計算される経験値。ダッシュボードのレベル・称号の元になる |
| 連続日数 | 「実施」または「軽め」の日が何日連続しているか |
| 称号(Badge) | 累計XPのしきい値ごとに設定されたレベル名（例: Lv5: 鉄の意志） |

## 3. 想定利用者・利用シーン

- 個人（利用者本人）が、その日行った筋トレ内容をスマホ/PCから記録する。
- v1では**単一利用者**を前提とし、ログイン認証機能は実装しない（家計簿機能と同様の方針）。
- 主な利用シーン
  - 筋トレを終えた後、その日の種目・セット・回数・重量・時間・RPE・気分・メモを記録する
  - 休養日も「休み」として明示的に記録し、サボりと区別する
  - ダッシュボードで現在の連続日数・累計XP・現在Lv・称号・今週の達成率を確認してモチベーションを保つ
  - 週末に週次レビューで「勝ちパターン」「来週の調整」を振り返る
  - 種目マスタ・称号マスタを必要に応じて編集する

## 4. データモデル

### 4.1 テーブル一覧

| テーブル | Excelの対応シート | 概要 |
|---|---|---|
| `exercises` | Menu_Master | 種目マスタ |
| `workout_days` | Workout_Log(日単位のヘッダ部分) | 1日ごとの記録（状態・気分・メモ） |
| `workout_entries` | Workout_Log(種目の詳細部分) | 1日の中の1種目分の記録。`workout_day`に対し複数持てる |
| `weekly_reviews` | Weekly_Review | 週次の自由記述（集計値は都度算出） |
| `badges` | Badges | 称号マスタ（必要XPしきい値） |
| `workout_settings` | Dashboard(上部の設定値) | 開始日・週目標などのシングルトン設定 |

`workout_days`はExcelのように366日分を事前に用意せず、**実際に記録がある日のみ行を作る**。ある日の行が存在しないことは「未記録」を意味し、連続日数の算出上は「休み」と同じ扱い（連続が途切れる）にする。

### 4.2 XP計算ロジック

`workout_entries`のXPは種目ごとに以下の式で算出し(Excelの数式を踏襲)、`workout_day`が「実施」の日は各エントリーのXP合計をその日のXPとする。

```
xp = ROUND( sets × reps × MAX(weight_kg, 1) / 20 + duration_min × 2 + rpe × 5 )
```

- 「軽め」の日は種目の詳細を問わず固定20XP
- 「休み」の日は0XP

### 4.3 レベル・称号ロジック

Excelでは「現在Lv」(`INT(総XP/250)+1`)と「称号」(Badgesテーブルのしきい値ルックアップ)が別ロジックで整合していなかった。本アプリでは**称号テーブルのしきい値に一本化**し、現在Lvは「現在の称号が何番目のしきい値か」から算出する。

初期データ(Excelの`Badges`シートをそのまま採用):

| 必要XP | 称号 | 説明 |
|---|---|---|
| 0 | Lv1: 入門者 | まずは記録開始 |
| 250 | Lv2: 習慣化見習い | 週に数回できている |
| 500 | Lv3: 継続者 | 記録が積み上がっている |
| 1000 | Lv4: 鍛錬者 | 筋トレが生活に入ってきた |
| 1500 | Lv5: 鉄の意志 | 休んでも戻れる状態 |
| 2500 | Lv6: ルーティン職人 | 安定して継続 |
| 4000 | Lv7: 筋トレ上級者 | 高い継続力 |
| 6000 | Lv8: Daily Quest Master | 完全に習慣化 |

称号マスタはDB管理とし、管理画面から追加・編集できるようにする。

### 4.4 連続日数

`workout_days`を日付降順に見て、直近の日から遡り、「実施」または「軽め」の日が連続する限りカウントする。行が存在しない日・「休み」の日は連続が途切れる。最高連続日数は全期間を走査して最大値を求める。

## 5. 画面構成

| 画面 | 概要 |
|---|---|
| ダッシュボード(`/workouts`) | 総XP・実施回数・現在Lv・称号・現在連続/最高連続・今週の達成率・今月XP・平均RPE・直近14日のXP推移グラフ |
| 記録一覧・入力 | 日付ごとの記録一覧、新規記録フォーム（種目マスタから選択、標準値を初期値として表示、1日に複数種目を追加可） |
| 種目マスタ | `exercises`のCRUD |
| 称号マスタ | `badges`のCRUD |
| 週次レビュー | 週ごとの自動集計値の表示＋「勝ちパターン」「来週の調整」の入力 |

## 6. 過去データ移行方針

Excelの`Workout_Log`（2026-06-16〜2026-09-08、記録済み分）を`rake`タスクでインポートする。

- 状態(実施/軽め/休み)が明示的に入っている行のみを`workout_days`として取り込む(空欄の日は取り込まない＝未記録として扱う)
- 「実施」の行は`Menu_Master`の種目名から`exercises`を検索/作成し、`workout_entries`を1件作成する
- インポート時のXPは再計算せず、**Excel側の値をそのまま保存する**(計算ロジックの見直しによって過去実績の数値が変動するのを防ぐため)
- `Menu_Master`は`exercises`としてそのままインポートする

## 7. 決定事項ログ

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 1日に記録できる種目数 | 複数種目を記録可能にする(`workout_days` 1 : N `workout_entries`) | 将来的な拡張性を優先 |
| 2 | 過去のExcelデータ(2026年6〜9月分)の扱い | DBへインポートする | XP・連続日数などの積み上げ実績を維持するため |
| 3 | 称号(Badges)の管理方法 | DBテーブルで管理し、管理画面から編集可能にする | 将来的にしきい値や称号名を調整したくなった場合に備える |
| 4 | 「現在Lv」の算出方法 | 称号テーブルのしきい値に一本化する(Excelの`INT(総XP/250)+1`は採用しない) | Excel版はLv番号と称号のしきい値が整合しておらず、矛盾を解消するため |
