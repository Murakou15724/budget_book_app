# PayPay CSVの取込条件と検証データ

要求・設計の正本は [Issue #69](https://github.com/Murakou15724/budget_book_app/issues/69) と [承認済み詳細設計](https://github.com/Murakou15724/budget_book_app/issues/69#issuecomment-6517586990)。

公式資料の確認日: 2026-10-30。[現行CSV項目・UTF-8案内](https://paypay.ne.jp/help/c0447/)、[履歴の種類](https://paypay.ne.jp/help/c0141/)。公式資料は全セル値の辞書ではないため、未知値を通常取引として推測しない。

## 対応書式

- UTF-8（先頭BOM可）、カンマ区切り、LF/CRLF。引用符、引用符内の改行・カンマに対応。
- 1回1ファイル、8MiB以下、見出しを除き1,000論理行以下。分割して同じ取込元へ送信できる。
- 見出しは `取引日 / 出金金額（円） / 入金金額（円） / 海外出金金額 / 通貨 / 変換レート（円） / 利用国 / 取引内容 / 取引先 / 取引方法 / 支払い区分 / 利用者 / 取引番号` の13列。順序のみ変更可。過不足・重複・類似名は拒否。
- 日時は `YYYY/MM/DD HH:MM` または秒付き。2000〜2099年の実在日時を日本時間として解釈。日付の補完をしない。
- 円金額は正の整数、または正しい3桁区切り。空・`-`・`ー`・`0` は金額なし。出金・入金の一方だけが正額であること。反映できる額は1〜2,147,483,647円。それを超える額は文字列で無丸め保持し保留。
- 全13列の原文、先頭ゼロ・大小文字を含む取引番号を保持。取引番号は数値化しない。原文の空欄は空文字。
- 通貨は空（外貨情報なしの場合）または `JPY`。海外額・レート・利用国が取引なし以外なら保留。外貨の換算をしない。
- 通常行は「支払い＋出金」か「給与＋入金」。支払い区分は空・`-`・`ー`・`一回払い`・`1回払い`、利用者は空・`本人`のみを対応条件とする。
- チャージ・送受金・カード精算・返金・取消・手数料・ポイント・外貨・受付中・未知の内容は保留。原文中の特殊語も確認対象。

不正なUTF-8、NUL、CSV構文、見出し、列数、サイズ・行数超過はファイル全体を422で拒否し、文書・候補・実績を作成しない。見出しのみは0行の完了文書。個別行の日時・金額等が不正な場合は行番号・理由と原文を保持し、他の有効行を処理する。

## 初期設定と通常の取込

1. service_keyが `paypay` の取込元を設定する。同じPayPay利用者では同じ取込元を再利用する。元口座は識別用。
2. 「CSV支払経路」で取引方法の原文と、反映口座・支払方法・クレカ状態を確認して設定する。取引方法は完全一致。複数方法を1口座へまとめない。設定キーは変更・削除せず、不要な経路は停止する。
3. CSV経路・支払経路・取引先・収支に一致する分類ルールを明示確認して設定する。画像ルールはCSVへ流用しない。
4. 自動化する場合は、一般設定の取込承認必須を無効化し、取込元のCSV自動反映を許可する。画像許可とは独立。支払経路・ルールも有効であること。
5. PayPayでCSVを取得し、CSV画面で取込元を選択して送信する。確かな新規通常行は個別操作なしで反映する。承認必須時は全行を候補に残す。

同一CSVの再送は現在の結果を返す。同番号・同原文は代表候補を参照し、別版は訂正候補。別番号や画像・手入力との類似は既存の口座・収支・金額・日付±7日で保留。設定を後からONにしても旧候補を自動化しない。候補・実績の訂正には共通確認画面を使う。

## 結果と保持

履歴は正常（手動反映）・自動反映・承認待ち・重複・対象外・エラーの排他的6区分。出金円・入金円・金額不明件数を別表示し、確定イベントの実績化額と原文記載額（重複を含む）を区別する。候補・文書の行は100件ずつ表示し、個別画面で原文全文を確認できる。

CSVは外部AI・金融APIへ送信しない。アプリは元CSVバイナリとファイル名を永続保存せず、原文13列・候補・イベントをDBへ保持する。本変更に自動削除機能は含まない。実データ有効化には#66のアクセス制限・HTTPS・DB/バックアップ保持方針の確認が必要。

## 架空データ

`spec/fixtures/files/paypay_csv/configured_ten.csv` は完全な架空データ10件。架空店・架空勤務先、残高・カード・銀行の3方法を使用し、金額1〜10円、先頭ゼロ付きの架空番号を含む。実利用者のファイル・個人名・口座番号は使用しない。

RSpecでは同条件の行をプログラムで生成し、10件自動反映、承認必須時0件、再送0件増加、複数経路、異常・境界・競合を検証する。検証結果は別記録に保存する。実CSV全種類の互換性・自動ダウンロード・金融API接続は検証対象外。
